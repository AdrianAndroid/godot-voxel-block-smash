## 硬性边界

- 保留已跑通的发射数据、物理推进、碰撞同色判断、体素删除、事件与计数逻辑。
- 所有新增表现复用原事件；新增代码用“【新增代码】”注释，原有注释保留。
- 保留可排查的创建/回收/粒子/交互日志，弹珠日志提供开关。
- 不以直接清空体素证明可通关；测试逻辑通过不等于肉眼表现验收。
- 粒子使用现有 voxel_destroyed 中删除前保存的 block 快照；在已提交删除事件后播放，避免为“删除前播放”更改事务或为失败删除播放效果。

## 按优先级实施与检查

1. 弹珠可视化：实例化 marble.tscn；颜色跟随炮台；逐帧只读物理位置；结束/重开/切关回收；空闲对象池复用并限制缓存数量；发射起点从屏幕槽中心投影，取消固定槽世界坐标；保留调试日志。瞄准线为可选，不作为本轮完成前提。超时落地需尊重现有物理退出语义，不从表现层私改球状态。
2. 碎裂：CPUParticles3D 设置立方体 mesh 和体素颜色材质；仅事件生成；维持数量上限及寿命回收；检查真机可见性和移动性能。
3. 手势：按下/拖动/抬起分离；抬起即使被 UI 消费也释放指针；结算/离开取消手势；检查无重复放置或发射。
4. HUD：取回模式调用原 return_turret；显示取回失败原因；胜负遮罩及重开、返回按钮；结算锁住玩法输入；操作提示。
5. 颜色池：由模型实际 color_ids 去重生成（青蛙四色）；初始池和随机排复用同一集合；兼容旧存档中不存在于模型的颜色并打印迁移日志。
6. 必须验收：APK 上正常操作“安放→发射→肉眼可见飞行碰撞→同色碎裂、块消失、计数下降→全部清空→胜利弹窗→重开”。不得用直接删除或改胜负状态代替。
7. 移动适配：视口拉伸和不同长宽比验证；球池、粒子上限；远处体素裁剪仅在性能证据证明必要时评估（当前单 MultiMesh，不贸然拆分）；连续30局不闪退/内存趋势，稳定≥30 FPS。

## 顺带发现的相关缺口

- 重开/返回必须清理旧总线订阅、球表现、手势、粒子、音效，防止跨局累积。
- 恢复旧存档不能覆盖本次运行 generation；否则后续事件可能被陈旧事件校验拒绝。
- 现有 palette 限制只解决无效颜色，不证明弹量充足和关卡必然可解；必须实际完整通关，不能以命中过数块代替。
- 现有自动测试有直接删除体素测试分支，只能视作局部单元测试，不作为本轮通关验收，不新增此类捷径。
- 模拟器既有平均约10 FPS、T23不足30轮；历史“阶段7完成”不能当作本轮通过。
- APK版本号/哈希必须更新并关联本轮代码；手机旧APK或旧存档不能与新源码混淆。
- 屏幕起点投影失败、取回失败、满槽等需给出提示；旋转极限/不同分辨率应专项测试。
- 现有物理边界使用格空间，控制器传入中心的坐标语义需要另行核查；本轮不擅改碰撞核心。
