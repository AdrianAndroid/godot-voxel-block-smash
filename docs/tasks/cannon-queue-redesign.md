## 2. 本轮统一规则

### 2.1 队列与槽位

- 底部是五列队列，不再是固定九格；列内索引 0 最靠近炮位。
- 设计默认：只有各列第一门炮可点击上位；点击后方炮台提示“先使用前面的炮台”。避免不明确的任意抽取导致队列规则失效。
- 点击列首 → 原子检查空槽 → 移入最左空闲已解锁炮位 → 该列向上补位。无需再点炮位。
- 默认初始 3 个开放炮位，最大 5 个；另两个保留锁定视觉，用现有加槽道具解锁，不接广告。
- 炮位用固定 5 项数组、空值表示空位；中间炮台离开时其他炮台不横向跳位。调度始终用 turret_id，不依赖数组压缩。
- 五列初始长度可不同，非人为固定 3 行。耗尽的列保持空列；不自动凭空补充弹药。
- 不让合成手势占用普通点击。合成保留独立模式，未启用时点击只负责上位。
- 为防无目标炮台永久占满槽位，设计默认允许取回“没有在途弹”的剩余炮台，即使它曾经发射。取回到原列队首、保留当前弹数；有在途弹时先停止该炮新发射，待结算/返还后取回。

### 2.2 数量与颜色守恒

模型唯一颜色源为 `palette[color_id]`。炮台、弹珠、碎片、统计全部引用同一 color_id，禁止再独立生成一套近似色。

对每种颜色 c 定义：

```text
V0[c] = 开局该色体素数
V[c]  = 当前该色存活体素数
Q[c]  = 五列中该色剩余弹数
S[c]  = 炮位中该色剩余弹数
F[c]  = 已扣出且尚未结算/返还的该色在途弹数
D[c]  = 已确认删除的该色体素数

开局：Q[c] = V0[c]，S[c] = F[c] = D[c] = 0
运行：Q[c] + S[c] + F[c] = V[c]
全局：V[c] + D[c] = V0[c]
```

注意：用户所说“底部所有数字相加等于青蛙块数”在开局严格成立。炮台上位后，必须将炮位弹数一起统计；飞行时还需算在途弹，不能为了让底部数字始终相等而复制弹药。验收报告必须说明这个统计口径。

- 一发成功子弹只删除一个同色体素，随后回收，不再反弹继续删除多块。这是实现严格数量守恒的设计选择，替代旧 G04/G07 的持续多次消除语义。
- 发射失败不扣弹；发射成功 S--、F++；命中提交 F--、V--、D++；取消/失效 F--、S++。全程不凭空增减。
- 弹数归零但仍有在途弹时，炮台暂留原槽显示“0／结算中”，不再发射；最后一发成功结算才移除。若返还则恢复弹数。不能先销毁炮台再丢失退款归属。
- 在途弹每炮最多 1 颗、全局最多 5 颗（设计默认，复用原预算）。持续发射指命中/返还后冷却到期继续发，不是无限累积球体。
- 连击改为成功消除的连续命中序列（默认全局，1.5 秒无成功命中清零）；不再以同一球反弹次数统计。没有额外消块奖励。

### 2.3 自动发射

- 炮台有弹、没有本炮在途弹、冷却到期，且存在未预订、可到达的同色活体素时才发射。
- 未找到同色目标是正常等待，不扣弹、不刷错误日志、不判失败；炮位显示“等待同色目标”，旋转或消除暴露新表面后重新搜索。
- 不能把“模型内部存在同色块”当作“当前能命中”。必须以真实发射起点、弹珠半径和当前模型变换做最近碰撞验证，异色遮挡则不射。
- 旋转中允许球继续飞行，但以每个物理步的变换判断。途中被遮挡、超时或目标失效时取消返还；禁止穿过异色方块、隔空删目标或把表现动画当命中。
- 本轮默认直线飞行，不增加隐形穿透或自动追踪。持续旋转可能使球退回；停止旋转后应能稳定恢复射击。

### 2.4 与旧道具规则的冲突处理

- 随机排：只重排尚在五列中的现有炮台，保留 ID、颜色、弹量；不重生成弹药，不改变槽内/在途状态。没有可变化的排列则不扣次数。
- 速度×2：保留下一次成功发射速度加倍，不改变消除数量。发射失败不消耗待发标记；成功生成后按旧规则消费，途中返还只退弹药、不重复发放道具。
- 加槽：保留上限 5，不改弹量。
- 任意指：旧“异色也能消除”与每色严格守恒冲突。本轮设计默认改为“指定同色目标”：激活后选择一个炮位及可达同色方块，为下一发设优先目标；只在成功接受合法选择时扣次，取消/异色/不可达不扣次。界面名称改为“指定目标”，不得暗中保留异色消除。S08 同步旧 G10 和测试。
- 合成：仅显式合成模式内对两列列首的同色炮台操作，弹量相加，不截断、不造新弹；超过配置上限则拒绝。默认上限 160，选择取消不改变队列，成功结果落在目标列首。

## 3. 架构和数据契约

复用体素存活集、空间索引、MultiMesh、事件总线、存档仓库和表现对象池；仅在必要边界调整物理/命中事务，不能因为旧任务要求“只补表现”而保留盲射缺陷。

| 模块                                  | 责任与接口方向                                           |
| ----------------------------------- | ------------------------------------------------- |
| game_rules                          | 五列、弹量拆分、模型容量、射速、预算和布局参数；所有参数能从关卡配置完整读取            |
| pool_service 或 cannon_queue_service | 五列队列、守恒生成、重排、取回、合成；不处理视觉动画                        |
| slot_service                        | 固定五槽与所有权原子转移                                      |
| target_selector（新增）                 | 按 color_id 查询表面候选，验证可达性；输出 voxel_id、世界目标点、方向、失败原因 |
| shot_ledger（新增）                     | 目标预订、在途票据、命中/取消幂等结算、分色守恒审计                        |
| auto_fire_scheduler                 | 稳定 ID 调度，区分等待目标与异常；每炮一颗在途                         |
| projectile_system / ball_physics    | 真实扫掠碰撞、时间/边界退出，命中后停球，通知控制器结算                      |
| hit_resolver / game_controller      | 同色校验、预订与弹药事务、删除提交、终局判定                            |
| cannon_view（新增）、hud_presenter       | 共用炮台造型、数字、状态、队列动画与固定槽布局                           |
| main / gesture_router               | 模型区域输入、屏幕空间跟手、相机与槽口投影                             |
| level_session / repository          | 新版本快照、种子/模型版本、在途恢复政策                              |

建议状态契约（实现前在 architecture.md 同步最终类型）：

```text
session.queue_columns: Array[5]，每列 Array[turret_id]
session.turrets: Dictionary[turret_id -> CannonState]
session.slots: Array[5]，元素 turret_id 或 null
CannonState: id, color_id, ammo_remaining, origin_column, state, has_fired
state: QUEUED / LOADING / READY / WAITING_TARGET / FIRING / RETURN_PENDING / DRAINING
ShotTicket: shot_id, turret_id, target_voxel_id, color_id, session_generation,
            status(PENDING/HIT/CANCELLED), speed_modifier
reservations: voxel_id -> shot_id
```

每门炮只存在于一个容器；视图不是所有权来源；LOADING 阶段逻辑已在槽内但暂不发射。动画被跳过/重建不能造成炮台丢失。

新增通知建议 `queue_changed`、`slots_changed`、`turret_state_changed`、`shot_resolved`。先登记事件总线白名单、参数与唯一 event_id，再接入；不绕开去重和 generation 校验。`turret_fire` 继续承载成功创建球，`voxel_destroyed` 仅在删除成功后发送，表现不负责扣弹/删块。

### S03：按颜色守恒生成五列队列

**前置**：S01 颜色统计和 S02 坐标契约通过。

### S05：同色选靶、真实命中与弹药账本（核心）

**前置**：S04 事务通过；初期用小型确定性夹具，之后用完整青蛙。

1. 建立按色索引和暴露面候选缓存；删除后只更新邻域。候选优先按可见性、距离、voxel_id 稳定排序，避免每颗球每帧扫描所有 5000 块。
2. 从炮口世界坐标到目标暴露面点执行与实际球半径一致的扫掠，确认最近命中就是目标且颜色一致。只用细射线可能误判宽球可达，不足以验收。
3. 调度原子流程：选靶 → 预订 voxel_id → 尝试创建球 → 成功建立票据并扣弹 → 发 `turret_fire`。任一步失败释放预订，不扣弹/待发道具。
4. 两炮同帧抢同一块只允许一份预订。每次发射前复核目标存活、颜色、generation；每个 shot_id 只能从 PENDING 结算一次。
5. 飞行按真实物理扫掠更新。命中预订同色目标才提交；误撞异色/其他目标则取消返还，不删除任何块。本轮不实现临时换靶，避免未预订同色块被重复消费。
6. 命中事务内先校验票据及体素，再执行一次删除、账本结算和球回收，最后发布体素删除/命中表现通知。重复命中、旧代回调必须无副作用。
7. 超时（默认 3 秒，可按尺度校准）、出界、旋转导致遮挡、目标失效、销毁失败均走一次取消/返还；到达逻辑与表现分离，不能直接按飞行计时删除目标。
8. 首发在上位完成后下一物理步；后续按默认 0.25 秒最小间隔和每炮一颗在途约束推进。无目标显示 WAITING_TARGET；模型旋转/块删除/炮台状态改变触发重查，补充低频重试并限制每帧查询预算。
9. 记录 `shot_id/turret_id/target_id/color_id/reason`、扣弹前后、每色 Q/S/F/V；开发测试模式在每次事务后断言守恒。

**交付**：selector、ledger、物理/命中接口改造、失败根因与修复证据。  
**通过条件**：同色可达必有真实飞行命中与计数减一；异色遮挡不发射；无目标不扣弹；两炮争抢、旋转、目标取消与超时都守恒；不允许为了过测关闭碰撞或直接清体素。

### S06：炮台素材与命中表现

**前置**：S05 核心链路通过。

1. 制作自有卡通炮台：短粗炮管、可辨炮口、圆润炮身、底座；炮身主色由模型 palette 染色，炮口深色，数字白色粗描边。不能继续以纯色矩形称为大炮素材。
2. 队列和炮位复用 `CannonView`。推荐自制分层矢量/透明纹理加程序化炮管旋转；若用 3D 预渲染图，保留模型源与渲染说明。允许轻量程序绘制，但必须有明确轮廓和正式资源路径。
3. 数字至少支持 1～160，不被炮管遮住；小屏仍可读。排队、可点击、后排禁用、等待目标、发射后坐、结算中、锁槽都有不同状态。
4. 炮管朝目标屏幕投影转向；发射起点来自可见炮口，不再来自按钮中心。短后坐与炮口闪光只在成功发射后触发。
5. 弹珠使用同色亮球加浅色高光/拖尾；命中播放同色碎片和轻量光圈。修复原碎片 mesh 大小与粒子 scale 相乘后过小的问题，以体素尺寸为比例，默认碎片边长 0.08～0.18 个体素。
6. 保持粒子预算 ≤512，寿命 ≤0.8 秒，关闭碎片物理；池化/合批优先。每次成功删除只播放一次效果。
7. 素材记录作者、制作方法、源文件和日期；不从参考游戏截图抠图，不使用许可不明资源。

**交付**：炮台源文件/纹理/视图、状态预览、资源清单与效果证据。  
**通过条件**：队列/炮位明确看得出同一门大炮，颜色一致，数字清楚，炮口与球轨迹对齐，命中特效实际可见。

### S07：五列界面与完整上位表现

**前置**：S06 资源可用。

1. 按 S02 区域组装 HUD：模型上方、炮位居中下方、五列排队、道具贴底，避免全屏中心挤压。
2. 五列顶部对齐，每列至少能展示前三门；更深队列由下方裁切/遮罩和“还有 N 门”提示。设计默认队列整体可纵向滚动浏览，但只有实际列首可操作，不能通过滚动把后排变成列首。
3. 长列使用视图复用/可见窗口，不为所有炮台创建昂贵 3D 场景；保持每列逻辑顺序。
4. 点击响应先确认数据事务，再播放一门炮到槽位、该列整体上移的动画；支持操作期间 UI 重建，不能让动画成为唯一业务推进入口。
5. 保留关卡号、剩余总数、连击、重开/返回；开发调试面板可显示每色守恒表，正式 HUD 不堆实现细节。
6. 输入优先级：结算/弹窗 → 道具目标选择/合成模式 → 队列滚动和炮台 → 模型旋转。拖队列不转模型，点击炮台不误当滚动；移动阈值默认 12 个逻辑像素。

**交付**：三种长宽比完整界面、点击上位及补位录屏/逐帧截图。  
**通过条件**：五列且长度可不同、后排正确禁用、满槽清晰提示、上下区域无遮挡、深列可浏览、鼠标和真机触摸一致。

### S08：道具、合成、连击与终局规则对齐

**前置**：S07 界面可操作。

1. 实现 2.4 的道具与合成规则，移除重生成随机排及异色万能弹路径。更新旧测试期望，不以旧测试要求保留已被替代行为。
2. 指定目标模式只接受同色可达且未预订目标，选择后若目标失效则退出优先锁定，恢复普通同色选靶；不额外退款已成功激活的道具，记录提示。
3. 连击只订阅成功消除事件，时间窗口与暂停相容；子弹结束不重复清零其他炮台的连击。
4. 全清且无未结算票据时胜利一次；结算锁输入、停止调度、清理视图。保留重开和返回。
5. 无当前同色目标不算失败。轮转/取回/队列/道具仍可继续时必须保持 RUNNING；默认长时间无进展 5 秒提示“旋转模型或更换炮台”。
6. 只有能证明没有剩余恢复操作的死局才判失败；无法证明时显示“暂时无目标”并提供取回/重开。守恒正确但未全清且弹药全空应记完整性错误，不能包装成正常失败。

**交付**：新版规则与测试、提示文案、胜负/停滞场景证据。  
**通过条件**：任何道具/合成不改变每色弹药总预算；暂停/恢复不补发；不会把被遮挡、满槽或空队列误判失败。

### S09：新存档与生命周期

**前置**：S08 规则稳定。

1. 快照版本升至 v2，保存 model_revision/hash、五列、固定槽、炮台字典、seed/RNG 状态、活体素、道具、规则版本；加载校验 ID 唯一、合法归属、颜色与每色守恒。

3. 用户返回列表/退出、后台暂停都走同一入口；窗口仅失焦是否保存按平台实现记录，但不能只丢掉球而不退弹。

1. 新局 generation 由本次运行生成，不从旧档覆盖；迟到的物理/动画/粒子回调不能改新会话。

**交付**：v2 schema、旧档备份说明、飞行中保存测试。  
**通过条件**：发射瞬间、最后一发、上位动画中、取回中、后台强制终止后恢复都不复制/丢弹；同色统计一致；重开连续执行无陈旧事件污染。
