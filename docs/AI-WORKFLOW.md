# Agent 工作流程

## 职责与边界
- Codex：架构、规范、文档、任务拆解排序、评审、风险分析和修复方案；不编写游戏实现或代替执行 Agent 初始化工程。
- Claude Code：唯一执行 Agent；素材检索、Goxel 处理、JSON 导出、工程初始化、脚本和资源修改；不得改架构、玩法、GDD 或跳阶段。
- 安卓模拟器测试执行端：运行构建、输入操作、收集日志/指标与画面现象文字；可由 Orca 提供调度和环境。调度能力未经验证不得宣称已启动。
- Codex 没有游戏画面输入，不依赖视觉判断；缺少观测证据等同未验证。

## 七阶段（严格依次）
| 阶段 | 内容 | 进入下一阶段的条件 |
|---|---|---|
| 1 | 项目初始化与架构 | 设计完成、Claude 空工程交付、Codex 验收通过 |
| 2 | 素材检索、Goxel、JSON | D05素材范围已明确，来源/许可/轴向/颜色/数量校验通过 |
| 3 | 核心底层框架 | 数据、体素渲染与索引、输入隔离、事件/状态契约验证；相关D03/D06/D07/D09明确 |
| 4 | 完整玩法 | 炮台池、槽与取回、有限合成、发射、碰撞/颜色、连击、消耗型四道具、胜负和独立关卡状态符合 GDD |
| 5 | UI、音效、特效 | 所有表现有观测项，D06/D07明确，数据绑定与性能证据通过 |
| 6 | 安卓打包、适配优化 | APK可安装、设备配置/签名管理/适配与性能审查完成 |
| 7 | 模拟器全量测试和修复 | GDD用例有报告；缺陷按修复任务实施并复测，最终评审通过 |

阶段1“设计完成”不能写成“工程已完成/验收通过”。后续目录预留不代表后续阶段已开始。未满足阶段门禁不得启动下一阶段。

## 每轮接手和交接
1. 先读 game-design.md、AI-WORKFLOW.md、dev-step-log.md；再读当前任务及 review-context.md。日志以最新记录为准，不重复开发已完成项。
2. Claude 只执行已授权任务；歧义引用 GDD 的 D 编号记录阻塞，不猜测数值。缺项不阻塞无依赖的当前阶段工作。
3. 每项任务必须有编号、前置条件、执行步骤、允许/禁止修改范围、交付物、观测验证项和失败处理。
4. Claude 提交 docs/review-context.md：任务/GDD/用例映射、文件清单、实现说明、环境版本、命令/退出码、证据路径、完成/阻塞/未验证项、风险。旧交接先归档到 docs/reviews/，文件名含时间与任务编号，不覆盖历史。
5. 测试执行端提交 docs/test-report.md：构建标识、模拟器设备/API/ABI/分辨率/渲染后端、输入/种子、预期与实际、PASS/FAIL/BLOCKED/NOT_RUN、指标、画面现象文字、日志路径。
6. Codex 按 GDD 审查渲染、颜色/反弹、弹量守恒、炮台所有权/取回/有限合成、连击、道具次数与下一发归属、胜负、关卡状态隔离及输入隔离；证据不足不通过。评审写入 docs/reviews/ 和步骤日志。
7. Bug闭环：现象与证据→根因（未证实标假设）→最小修改范围与步骤→回归用例→Claude交付→模拟器复测→Codex结论。只有失败项关闭且回归通过才更新状态。
8. “任务文档已下发”与“实际启动Claude”分别记录；没有调度回执不得声称 Agent 正在执行。

## 日志规范
只追加，不覆写历史。每轮 Codex 必须使用：

【时间】：实际日期、时区
【执行人】：Codex
【完成工作】：本轮产出、架构设计、任务拆解
【当前进度】：阶段、设计/执行/验收状态
【下发给Claude的任务】：编号、步骤、交付物、验收观测项及实际调度状态
【风险记录】：架构、性能、模拟器风险、效果歧义
【下一步触发条件】：Claude交付review-context.md后评审，列明其他门禁
