## 每轮接手和交接
1. 先读 game-design.md、AI-WORKFLOW.md、dev-step-log.md；再读plan.md、architecture.md、当前任务及 review-context.md。日志以最新记录为准，不重复开发已完成项。
2. Claude 只执行已授权任务；歧义引用 GDD 的 D 编号记录阻塞，不猜测数值。缺项不阻塞无依赖的当前阶段工作。
3. 每项任务必须有编号、前置条件、执行步骤、允许/禁止修改范围、交付物、观测验证项和失败处理。
4. Claude 提交 docs/review-context.md：任务/GDD/用例映射、文件清单、实现说明、环境版本、命令/退出码、证据路径、完成/阻塞/未验证项、风险。旧交接先归档到 docs/reviews/，文件名含时间与任务编号，不覆盖历史。
5. 测试执行端提交 docs/test-report.md：构建标识、模拟器设备/API/ABI/分辨率/渲染后端、输入/种子、预期与实际、PASS/FAIL/BLOCKED/NOT_RUN、指标、画面现象文字、日志路径。
6. Codex 按 GDD 审查渲染、颜色/反弹、弹量守恒、炮台所有权/取回/有限合成、连击、道具次数与下一发归属、空位不可选和粒子不参与碰撞、胜负、关卡状态隔离、输入隔离、素材来源授权及跨模块通知只走event_bus；证据不足不通过。评审写入 docs/reviews/ 和步骤日志。
7. Bug闭环：现象与证据→根因（未证实标假设）→最小修改范围与步骤→回归用例→Claude交付→模拟器复测→Codex结论。只有失败项关闭且回归通过才更新状态。
8. “任务文档已下发”与“实际启动Claude”分别记录；没有调度回执不得声称 Agent 正在执行。

## 事件总线强制规范

跨模块通知统一使用event_bus，保留已约定的严格规则；不以“优先”作为绕开总线或大量获取节点引用的理由。只有Codex可修订事件契约，Claude不得自行增加/改名。固定事件：level_loaded、voxel_destroyed(block_data)、ball_hit_voxel(ball, block)、ball_out_of_bounds、turret_fire、turret_merged、combo_update(combo_num)、level_win、level_lose、item_activated(item_id)。完整参数、meta和时序见architecture.md。命令协调与模块内组合不等于跨模块通知，按架构显式接口执行。

## 素材管理强制规范

1. 按用户指定优先来源检索：Sketchfab的CC0 vox、VoxEdit市场CC0、Kenney、OpenGameArt、itch.io CC0资源。平台名称不等于具体素材已获许可，必须逐资产核对许可文本。
2. 禁止小程序截图抠图、授权不明、CC-BY（需署名）、付费素材；免费可下载不等于可入库。外部素材优先CC0，其他许可不得由Claude自行决定采用。
3. 原始vox放assets/vox_source/；Goxel编辑源放assets/source/goxel/；关卡配置放assets/levels/，体素模型JSON仍放assets/models/json/并由关卡引用；UI贴图放assets/textures/ui/，粒子贴图放assets/textures/particle/；授权存档统一assets/license/，不用旧licenses路径。
4. 每项资产记录源链接、作者、许可原文/链接及本地存档、取得日期、原始文件与修改记录；检查实际资产的许可，不按站点笼统推定。
5. 素材不足先由Claude提交缺口，按既定青蛙范围手动Goxel绘制；其次可提出AI生成UI图标方案，由Codex确认任务范围。自制记录作者/制作过程；AI素材记录工具、日期、提示词及适用条款，不伪标CC0。
6. 评审观测项：每个入库素材均能追溯授权/自制记录，禁止项为零；缺记录的资产不能通过阶段验收。阶段1只建目录/模板，不提前检索下载。
