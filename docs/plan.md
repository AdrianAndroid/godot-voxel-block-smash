# godot-voxel-block-smash 七阶段执行计划

版本：PLAN v3，2026-10-26。来源：用户本轮七阶段方案；玩法依据 game-design.md（GDD v6）。Godot 4 / Intel Mac mini / Goxel；个人学习原型，不发布、不分发，最终验收在安卓模拟器。

## 给接手 AI 的执行协议

1. 先读 game-design.md、AI-WORKFLOW.md、dev-step-log.md，再读本计划、architecture.md、当前任务单和已有review-context.md。不存在的交接文件记未交付，不能假设完成。
2. Codex负责设计、拆解与评审；Claude Code负责工程、脚本、资源及修复。测试执行端提交模拟器证据。未经用户重新指定，不改变职责。
3. 严格按阶段1→7执行。阶段内按下表编号与依赖推进；每阶段完成后交接，Codex评审通过才能进入下一阶段。本计划是执行路线，不是已执行记录，也不代表已启动任何Agent。
4. 表中“前置”包含上一阶段验收通过。D编号引用GDD未决项：只阻塞依赖该项的任务；可继续无依赖工作。测试夹具的临时数值必须标TEST_ONLY，禁止作为正式玩法默认值。
5. 允许修改当前阶段列出的交付目录及相关测试、交接和日志；禁止执行方自行改GDD、架构、增加玩法、覆盖已有证据。发现冲突先记录需求/任务编号，由Codex给出修订。
6. 每个任务失败时：保留原始命令、退出码、日志、复现步骤；标FAIL或BLOCKED；记录原因和恢复条件；禁止跳过验收或伪造PASS。所有表行均适用本失败处理规则。
7. 观测证据使用行为事件、状态前后值、量化指标、测试者画面现象文字。截图可作附件，不能替代文字/日志；Codex不预览游戏画面。“流畅/好看/不明显掉帧”必须转为批准阈值。
8. 每轮更新dev-step-log.md；每阶段提交review-context.md和test-report.md，旧交接归档docs/reviews/。未运行用例标NOT_RUN；有缺失前提标BLOCKED。

## 模块名称映射与调用方向

| 用户方案模块 | 架构实现职责 |
|---|---|
| VoxelManager | VoxelLoader/Data + VoxelState/Renderer/SpatialIndex |
| BallPhysicsSystem | ProjectileSystem + CollisionSolver；颜色业务归HitResolver |
| UIGridPool | PoolService + TurretState + HudPresenter池展示 |
| SlotSystem | SlotService；通过GameController提交发射 |
| ItemSystem | PropService；库存、待发与Shot快照分离 |
| GameStateManager | GameController + OutcomeState + LevelSession/Repository |
| 事件总线 | EventBus发布已提交领域事件，EventRecorder订阅诊断；UI/音效/效果只读订阅 |

调用方向：输入/UI请求→GameController→领域服务原子提交→EventBus→渲染/HUD/音效/诊断。事件总线不拥有玩法状态；监听方不能通过回调顺序决定扣弹、删除或胜负。每关显式注入并在切关解绑，不新增全局Autoload。JSON模型保持schema_version=2；关卡配置引用模型与批准规则，不重复存储一套逐块颜色格式。

## 本轮补充的强制实现约束
所有跨模块通知全部走event_bus，禁止大量直接节点引用；固定十个事件及参数/时序以architecture.md“固定事件清单”为准。阶段3入口脚本为event_bus、game_state、input_mutex、level_loader、voxel_manager、ball_physics；已有细分模块作为入口内部组件，禁止维护重复状态。阶段1仅创建可解析占位，具体逻辑按本计划阶段实现；占位存在不等于模块完成。阶段5包含通关/失败弹窗并验证与终局事件一一对应。

素材路径补充：粒子贴图统一assets/textures/particle/；外部资产授权存档统一assets/license/。素材不足先手动Goxel绘制，其次提出AI生成UI图标方案；不伪造自制/AI素材的CC0声明。阶段1～6的自测与阶段7全量测试均须保留证据。
