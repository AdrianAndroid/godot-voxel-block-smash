### 2.1 弹珠表现

- 监听 turret_fire：args[0] 为炮台快照，args[1] 为 ball_id。从 marble.tscn 实例化或从 idle 池取球；使用模型 palette[color_id]。使用每实例独立材质或缓存的只读逐色材质，禁止改共享材质导致全部球变色。
- active 映射 ball_id → Node3D；idle 为已隐藏节点。初始可懒分配，idle上限建议32（原型可配置值，需性能验证）。不得因为缓存满而拒绝已成功发射球的可见表示。
- 每帧读取 ball_snapshot(id).pos，写 global_position；只遍历 active 渲染映射，不依赖私有 _balls 字典。
- ball_out_of_bounds 或快照 inactive/不存在时幂等回收；池满才 queue_free。clear 在重开、返回和结算时回收所有表现球。
- 不从表现层自行修改物理活跃状态。原有 out_of_bounds/max_bounces 作为退出来源；若要求新增时间上限，先证明确有滞留球，再由控制器执行统一结束事务并走既有结束事件，禁止视觉消失但物理球继续计数。此项记录为条件性缺口。
- debug_logging 可配置，记录 acquire/recycle、ball_id、generation、位置、池大小；默认开发包开启。

### 2.2 屏幕炮台与发射原点

当前 (i-2)*2/-half*0.8 固定坐标必须移除。HUD提供实际按钮 global_rect 中心，Camera3D.project_ray_origin/normal 得到世界射线。选择与现有有效物理区域一致的入口面/射线交点作为原点，确保 unproject_position(origin) 与按钮中心吻合。

必须处理：视口拉伸坐标一致、不同宽高比、模型旋转后的 world_from_grid、边界半径余量、射线无交点。禁止静默改回硬编码起点。先确保HUD槽行处于可投影区域；不合法时给出明确提示并不扣弹。

注意现有边界注释/计算的格空间中心与控制器传入世界中心存在语义疑点；Claude应先用只读坐标探针验证。如修正必须改核心碰撞行为，单列问题和最小方案，不能夹带在表现修复中。

瞄准预览线为可选开关，默认可不做；不增加自动瞄准或自动消除。

### 2.3 碎裂效果

现有 CPUParticles3D 未设 mesh。设置 BoxMesh 和 StandardMaterial3D；颜色由 voxel_destroyed.args[0].color_id 查询当前模型 palette。位置使用 args[1].point（世界坐标），或由快照grid通过模型变换求块中心。

**事件时序裁决**：用户要求“删除之前生成”与“不改变现有删除核心、复用消除事件”存在时序冲突。沿用删除前快照、删除成功后播放，保证同帧可见反馈，不提前播放失败删除的粒子，不改事务顺序。

现有16个/0.8秒/512总量可作为首轮基线，不先增加粒子成本。一次事件一次burst；保留数量上限；超额丢弃表现不影响逻辑。定时回收必须校验实例有效性；clear后旧timer回调不能减掉新会话粒子计数（generation或每批token隔离）。连击飘字也应清理并停掉旧tween。

### 2.4 触摸与HUD

- ScreenTouch.pressed → press；ScreenDrag → drag；ScreenTouch非pressed → release。释放可在 _input 中统一处理，避免抬起落在UI时 _unhandled_input 收不到；释放应幂等。
- 失焦/退后台/结算/返回/重开执行 cancel_all。UI消费的按下不能旋转模型。验证多指与鼠标模拟不重复发射。
- “取回炮台”采用显式取回模式：按钮进入模式，下一次点击槽调用已有 return_turret(index)，显示未发射限制等失败原因。按第10节最新规则，入槽自动连发；点击槽不额外产生射击。
- 结算为全屏输入遮罩+文字+重开/返回按钮；控制器已有not_running约束仍保留，不能只依赖遮罩。
- 导航使用HUD信号通知Main，不由HUD直接销毁会话节点。重开使用空restore；返回保存当前局并停止帧推进，重新显示关卡列表。
- 满槽、合成失败、取回失败、发射失败须提示；只在命令成功时显示成功状态。

## 3. 会话生命周期（必须与UI一起实现）

推荐顺序：禁用交互 → 保存（仅返回或退出，重开不恢复旧局）→ 停止旧控制器推进 → 解绑旧level订阅 → 回收球与粒子/声音 → 清手势 → 创建新会话/回到列表 → 绑定表现 → 启用交互。

检查总线去重表：BallPhysics的新实例可能从相同序号重新生成event_id。重开后必须保证新会话事件不会撞旧去重ID。可每局使用全新总线并重新绑定，或采用已验证的全局唯一ID方案；不修改核心命中/删除算法。旧总线不得被定时器/闭包长期保留。

恢复存档后，当前session_generation必须保留本次运行代号，与bus generation一致，不能被历史存档代号覆盖。重开后及时保存新局，避免立即退出后继续旧局。若初始化失败，保持可恢复的列表和错误提示，不留半绑定界面。

## 4. 颜色有效性与可解性

1. 从加载的模型实际color_ids去重生成候选集，不从palette全表或写死[1..7]抽取；校验非空。
2. 注入本局rules.palette_color_ids，使初始生成与shuffle共享限制。每次生成校验抽出的颜色属于有效集合。
3. 旧存档可能保留无效色炮台：定义显式迁移（只替换无效color_id为当前有效色，保留id、弹数、来源格、has_fired；记录日志），或提示用户重开；不得无提示清空存档。
4. **四色限制不是通关保证**。弹量、各色块数、球反弹后的持续命中机会、有限shuffle仍需实战评估。若正常流程无法清空，记录碰撞轨迹、剩余各色数量、弹量与道具，提出最小配置调整，不能偷偷改变核心规则或无限补弹。
5. 现有失败条件只处理池/槽全空；存在“有炮台但没有可消目标”的软锁风险，须验证并报告。该规则修订不夹带进表现层。

## 5. 移动适配与性能

- 设计分辨率沿用1080×2400，评估canvas_items + expand；UI使用锚点/容器，不混用窗口物理像素和逻辑视口坐标。
- 检查长屏、短屏、安全区、底部手势区、5槽宽度和提示换行。结算遮罩必须覆盖全部可触区域。
- 优先球池/粒子上限/会话清理；只在测量后决定远处裁剪，当前单MultiMesh不应为未证实收益拆成逐块节点。

## 10. 用户明确变更：入槽自动连发（优先于前文历史点击发射描述）

2026-10-26 用户明确：炮台只要处在上方炮位便持续连发，弹数降到0后消失。此项是用户确认的玩法变更，不再列为可选或待确认。

### 调度设计（Claude实施）

- 在控制器编排层新增 AutoFireScheduler，复用现有 fire(slot_index, origin, direction) 原子发射接口，不改碰撞、同色消除或体素删除。
- 安放成功后注册 turret_id；首发可在下一物理步执行。按固定物理时钟计算冷却，首轮间隔建议0.25秒/发，为可配置执行默认值，并非用户指定数值。不按渲染帧率发射。
- 多个炮位独立冷却并同时工作，不等待上一颗球出界；不需要玩家逐次点击，点击槽不得额外重复触发发射。
